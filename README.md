## 깃허브 계정 생성시 주의사항
- 신청서에 대해 관리자가 승인하면 깃허브에서 초청 메일이 발송됩니다.
- 깃허브 Enterprise 멤버십 초청 메일 수신후 7일 내에 메일인증을 완료해야 하며, 7일 경과시는 초청장이 자동 만료됩니다.(만료 후에는 재신청 필요)
- 신청한 조직/프로젝트 코드로 깃허브 Enterprise 사용료가 매달 이관 요청됩니다. (CL/AI 사용료 예산이 있어야 함)
- 깃허브 정책은 계속 업데이트 중이라 변경될 수 있으며
- 코파일럿은 신청자 계정이 깃허브 Enterprise 조인 완료된 후에 신청 가능합니다.
  (조인이 완료되지 않은 상태에서는 기능적으로 코파일럿 할당 불가)

## 깃허브 계정 탈퇴 관련
- 깃허브 계정은 개인이 소유한 것이며, 표준저장소 관리자가 계정을 삭제할 수 없습니다.
- 표준저장소 사용을 원하지 않을 경우, 개인의 Settings에서 조직을 탈퇴(Leave)하면 됩니다.
- 단, 표준저장소 관리자에게 요청할 경우 사내용 표준저장소에 대한 접근 권한만 삭제할 수 있습니다. (즉, AX 표준저장소에서 멤버십 탈퇴처리)
- 멤버십 탈퇴는 다음의 경우에 발생합니다. (사전 통보 없이 멤버십 삭제)
 1. 프로필 표준을 준수하지 않는 경우
 2. 비용정산 대상 프로젝트 코드와 매핑되지 않는 경우
 3. Enterprise 멤버십 획득 이후에 Username을 변경한 경우 : 멤버십 관리를 위해 Username은 중요한 키가 되는데, Username 변경할 경우 관리자가 승인하지 않은 계정이 되어 강퇴됩니다.

## 깃허브 비용부과 프로세스
- 깃허브 사용료는 관리자가 계산하는 것이 아니며, MS에서 계산하여 청구하는 것입니다. (표준 저장소 관리자는 전체 비용 구조를 알지 못합니다.)
- MS에서 청구된 내역에 대해 표준저장소 관리자는 깃허브 Enterprise의 Usage Record를 통하여 사용자별로 청구된 비용을 추출하여 조직으로 이관처리할 뿐입니다.
- 따라서, 청구된 내역에 대해 사용자 Username과 신청시 작성한 프로젝트/조직 코드와 매핑할 수 있어야 합니다.
- 또한 해당 조직에는 CL/AI 예산이 수립되어 있어야 합니다. (비용 이관시에는 담당 PM/팀장을 참조)
- 따라서, 프로젝트 코드가 매핑되지 않는 계정은 조직에서 탈퇴처리될 수 있습니다.

## 깃허브 활동 로그 감시
깃허브 활동 로그 추적은 **소스 관리 및 보안 감사**의 목적이기 때문에 다음의 활동들만 인지됩니다.
- 소스 관련 작업 (push / pull / commit 등)
- workflow 실행
- 리파지토리 환경변수 작업
- 리파지토리 owner인 경우, 팀 멤버관리 작업 등
- Issue 할당 및 관련된 코드 작업

깃허브 활동 로그에서 **인지되지 않는 사용자 활동**은 다음과 같습니다.
- 웹 화면에서 단순 로그인
- Issue 생성 및 Comment 등록 

_따라서, 깃허브에서 소스 및 DevOps 작업에 참여하지 않고 이슈만 관리하는 경우 깃허브 활동 로그에서 추적할 수 없으므로 비활동 휴면 사용자로 간주될 수 있습니다._
